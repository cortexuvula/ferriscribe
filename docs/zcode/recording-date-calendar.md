## Resolved UX
1. Active ONLY. Preserve always-visible Active/Trash tabs; Trash recovery and deletion-time picker unchanged. Switching to Trash and back preserves Active date/search. Default All dates.
2. Labelled `Choose recording date` button beside search; wrap it onto a separate row at narrow widths. Nonmodal labelled calendar popover; no new package. Initial visible month = selected day if any, else newest populated month. No automatic day selection.
3. Seven weekday columns; ONLY populated days have visible date numbers/buttons. All other cells blank inert spacing, aria-hidden. Counts can appear on day buttons, with accessible full-date/count labels. `aria-pressed` marks selection; don't rely on color alone.
4. Prev/next jump to adjacent populated month. Year select contains populated years; month select contains populated months of that year. No empty month/year choices; old years reachable directly. Buttons disabled at endpoints.
5. Select one day, close popover, retain search. Chip: `Recorded on <localized full date>` and `Clear recording date`. All dates/clear date retains search. Availability remains independent of search. Search is intersected in SQL with selected day BEFORE LIMIT.
6. Zero-state wording distinguishes no active recordings, search-only no matches, date-only no rows, and `No recordings on this date match your search`. Clear search/date independently. Keep search input visibly synchronized on tab remount and programmatic clear; pending debounce cannot reintroduce a cleared filter or overwrite a newer query.
7. Preserve selectedRecording and unsaved editor drafts when filtering; never automatically choose another row. Where a notice is shown, do not infer filter exclusion from absence in a PAGINATED list. A known day mismatch can say `Selected recording is outside the selected date.` Unknown search membership must not be asserted from missing loaded row. Actual deletion keeps existing selection-clearing behavior.
8. Move all to Trash stays GLOBAL, reachable even with zero filtered matches when authoritative activeTotal > 0. Dialog explicitly: `This moves all active recordings to Trash, including recordings outside the selected date and current search.` Existing retention consequences and actual-count Undo remain.
9. Keep selected date through transient failures/search-only zero matches. On successful current availability refresh proving that its last active recording disappeared, clear ONLY date, preserve search, reload and politely announce `No active recordings remain on <date>. Showing all dates.` A failed/stale availability fetch must NEVER clear the filter.
10. Ordinary buttons in labelled region, NOT role=grid without full grid keyboard behavior. Trigger aria-expanded/controls; Enter/Space activate; Escape closes and restores trigger focus; outside click closes without changing selection. Focus selected visible day else first day/control on open; safe focus if refresh removes focused day. Loading/failure/application status announcements once, not per cell. Theme tokens, visible focus, usable targets, bounded popover width/height/scrolling. No PHI in live status or error logs.

## Backend and state architecture
- Add `list_recording_creation_times` command/wrapper returning ONLY normalized active created_at instants, one per recording (duplicates retained for counts), from all active rows. No patient names, filenames, paths, transcripts, generated documents or metadata in availability payload. Group into YYYY-MM-DD/count using browser LOCAL date components, never UTC substring or current fixed offset. This timezone-free timestamp projection deliberately avoids backend OS timezone mismatch and a new timezone dependency. It is O(n) timestamp-only metadata, not full-row loading; document this tradeoff, no new index until measured necessary. Parse legitimate legacy UTC/RFC3339 offsets, propagate error instead of silently manufacturing empty availability.
- Add one `query_recordings` command/wrapper and repo method for the Active store: optional search text and optional paired UTC startIso/endIso, limit(default 50, max 200), offset(default 0), returning RecordingSummary[]. Incomplete/malformed/reversed bounds rejected, never unfiltered fallback. Parameterized SQL: active rows AND optional half-open creation interval AND optional literal-term FTS membership BEFORE LIMIT/OFFSET. Date comparisons normalize offsets/legacy forms (e.g. julianday). Stable newest-first timestamp then id tie-breaker; search uses the same stable chronological order for a coherent date browser (deliberately not relevance order). Preserve all summary fields/flags/tokens/sync badge without projecting full clinical documents. Keep old list/search interfaces for other callers.
- Centralize Active store list/query paging around the composite {date,search}. Explicit raw consumed offset, hasMore from raw page, dedup visible IDs only. Reset/invalidate in-flight first/next pages on filter changes AND mutation refreshes; stale finally handlers must not unlock/overwrite newer requests. Load-more also no-op during first-page load. Preserve public load/search entry points used by app events. Every refresh uses CURRENT filters; no transient unfiltered row injection from restore caches.
- Independent token-guarded availability state (loading/error/loaded). Share refresh/invalidation path across mount, Active return, create/import/generation refresh, delete, restore variants, bulk move/undo, manual/background sync and recording-updated events. Review ALL refresh producers. Avoid recursion between availability-triggered date reset and list reload; stale response cannot validate a newer dataset generation. Timezone changes across remount/open must rederive availability/bounds consistently.
- First-page failures render retryable error instead of old mismatched rows or fake empty success. Load-more failure retains already-valid results and offers Retry. Sanitized/static UI errors; no transcript/names/search text in logs. SQLCipher/privacy/CSP and local-only inference invariants unchanged.
